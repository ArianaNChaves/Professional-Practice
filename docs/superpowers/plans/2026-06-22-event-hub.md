# Event Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a centralized, type-safe runtime event hub for game communication, then migrate existing static events incrementally across simple UI/input and feedback flows while leaving enemy logic unchanged.

**Architecture:** Use a small C# event hub with typed payload structs/classes and explicit subscribe/unsubscribe lifecycle. Keep the first migration additive so current gameplay still works, then remove old static events only after each behavior is verified in Unity Play Mode.

**Tech Stack:** Unity 2022.3.62f2, C#, MonoBehaviour lifecycle, Input System, existing prefabs/scenes.

---

## Current Findings

- The active enemy flow still uses `DeprecatedEnemy` and `BaseEnemy`, and will remain unchanged in this plan.
- `EnemySpawner` gets `DeprecatedEnemy` from `PoolManager`.
- `DeprecatedEnemy.Activate()` currently publishes `DeprecatedEnemy.OnSpawn`.
- `EnemyManager` listens to spawn and gives waypoint targets.
- `PlayerEnemyIntereact` listens to spawn and gives the player reference.
- `DeprecatedEnemy.Death()` currently publishes `DeprecatedEnemy.OnEnemyDeath`.
- `Timer` listens to enemy death and subtracts time through the existing static event.
- The removed police/refactor path is no longer referenced by prefabs/scenes.
- `PauseManager.OnDisable` is fixed and now unsubscribes correctly.

## File Structure

- Create `Assets/Scripts/Events/GameEventHub.cs`: central static hub with subscribe, unsubscribe, publish, and clear.
- Create `Assets/Scripts/Events/GameEvents.cs`: event payload types grouped by domain.
- Modify `Assets/Scripts/Player/Player Inputs.cs`: publish input events through the hub.
- Modify `Assets/Scripts/UI/PauseManager.cs`: listen to the hub for pause.
- Modify `Assets/Scripts/UI/TutorialInteraction.cs`: listen to the hub for interact.

## Notes For Future Features

- New features should add a payload type in `GameEvents.cs`, publish from the owner of the state change, and subscribe in presentation/feedback systems.
- Prefer payloads with explicit data over parameterless events once the event affects gameplay decisions.
- Subscribe in `OnEnable` and unsubscribe in `OnDisable` for MonoBehaviours.
- Keep gameplay ownership local: the event hub announces that something happened, but it should not own enemy AI, pooling, timer rules, scene loading rules, or audio playback rules.
- Enemy spawn and death events are intentionally excluded from this plan until the enemy logic is stable enough to revisit safely.
